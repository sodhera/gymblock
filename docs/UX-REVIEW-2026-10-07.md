# GymBlock UI/UX review: 7 Oct 2026

Walked as a brand-new user on **iPhone 18 Pro, iOS 27.0** (fresh simulator, no demo data, Debug build).
Every screen below was seen in the simulator; code references explain *why* behaviour happens.

---

## TL;DR

The in-workout loop is good: a repeat set is **2 taps** (Start set → Finish set). The problems are everywhere around it.

1. **Feature #1, app blocking, is invisible.** Onboarding never sets it up, it is **off by default**, and it lives at Workout → ⚙︎ → Focus demo → toggle. A user who finishes onboarding gets no blocking and is never told.
2. **First set takes ~26 taps over ~20 screens.** Onboarding alone is 16 taps and 17 screens before the user sees the app.
3. **Ending a workout takes 1 tap with no confirmation** (during rest/setup), and the button sits right under Start set.
4. **Weight entry is the most expensive common action** (4 taps + digits), and fast typing drops digits (typed `60`, saved `6 kg`).
5. Onboarding collects data (sets, reps, rest habits, scrolling minutes) that the workout screen **never uses**.

---

## Tap budget (measured)

| Task | Taps today | Screens | Target |
|---|---|---|---|
| Install → app home | 16 | 17 | ≤ 8 |
| Home → first set logged (new exercise) | 10 + digits | 6 | ≤ 5 |
| Repeat set, same weight | **2** ✅ | 1 | 2 |
| Change weight between sets | 4 + digits | 2 | 1–2 |
| Switch to next exercise | 2 (+4 for weight if new) | 2 | 1 |
| Turn blocking on | 4, undiscoverable | 3 | 0 (on by default after setup) |
| End workout | **1, no confirmation** ⚠️ | 1 | 2 (confirm) or a long-press |

## P0: fix before anything else

### 1. Blocking has no setup, no default, and no presence
- `focusEnabled` is set to `false` on onboarding appear (`OnboardingJourney.swift:83`) and only reachable via `Home.swift:106` (Settings → "Focus demo").
- No Screen Time / FamilyControls permission step and no "choose apps to block" step in onboarding.
- Home and the session screen show nothing about blocking unless the toggle is on (`Session.swift:50`), and even then it's a 13 pt grey "Focus demo" label.
- The paywall benefit list ("Measure your set and rest time. See your workout progress.") **doesn't mention blocking**.

**Fix:** Add one onboarding step after the scrolling question: *"Which apps distract you?"* → FamilyActivityPicker → permission. Default blocking ON. On Home, show a persistent status row ("Instagram, TikTok + 3 blocked during workouts · Edit"). During a workout, show a small lock chip in the nav bar. (Keep the "simulated" label honest while it's a prototype.)

### 2. "End workout" ends instantly during rest
- `Session.swift:71`: `if active { ending = true } else { store.finish() }`. Confirmation only exists mid-set.
- The button is 48 pt tall, directly below the 72 pt Start set button. With sweaty hands mid-rest, this is the most likely mis-tap in the app, and it's destructive (the session closes and Summary shows).

**Fix:** Always confirm, or move End to the nav bar (top-left "End") where it can't be hit by accident.

### 3. Typed weight loses digits
- Typed `60` quickly → saved **6 kg**. Typed slowly → 60 kg. Root cause is likely `SelectNumberOnFocus` (`Session.swift:324`), which calls `selectAll` on the next runloop after focus and races the first keystrokes.
- Silent data corruption in a logging app is a trust killer.

**Fix:** Select-all synchronously in `textDidBeginEditing`, or start with an empty field and the previous value as placeholder.

### 4. Internal annotation shipped to users
- Focus story shows: *"Your proposed copy · Unverified health claim"* under the nervous-system quote. That's a dev note, and it actively tells users the claim is unverified. Either drop the quote or drop the label; showing both is the worst of both.

## P1: onboarding (17 screens → aim for ≤ 8)

Current flow: Welcome → days/week → visit length → reps → sets → exercises → scrolling → minutes → breaks → rest habit → logging habit → set-timing habit → brain story → arm story → records story → paywall.

| Screen | What I saw | Issue | Recommendation |
|---|---|---|---|
| Welcome | Headline, tilted **blank black phone**, caption "Workout" | The illustration is static and communicates nothing; "Workout" under it is unexplained | Show the actual value: a phone with Instagram/TikTok icons greying out → "Blocked while you train". Animate once. |
| Days/week | Slider 1–7 | "workout" used as a verb → "work out". Fine otherwise | Keep, but consider dropping (unused in-app) |
| Visit length | Wheel, 5-min steps | OK | Keep. It feeds the scrolling estimate |
| Reps / Sets / Exercises | Three separate wheels | Three screens for one concept ("your typical session"). Wheel shows "1 sets". Values are **never used** in the workout (no "Set 2 of 3", no rep target) | Collapse into one screen with 3 compact steppers, or cut entirely and infer from the first 2 workouts |
| Scrolling? | Yes / Sometimes / No | This is **the** question for a blocking app and it's 6th | Move it to screen 2 |
| Minutes | Wheel, 0.5-min steps | Ambiguous: per break or total? | "Minutes on your phone **per rest**" |
| Breaks | "Out of 17 possible breaks" | Makes users do arithmetic | Drop; derive from Yes/Sometimes |
| Rest / logging / set-timing habits | Three one-tap lists | "Not sure" makes no sense for "Do you record your workouts?" Answers are never referenced again | Keep at most one (rest timing). Drop "Not sure" where the user obviously knows |
| Brain story | Animated brains + 10-min estimate | The **personalised payoff** ("10 min of estimated scrolling per visit") is 14 pt grey text below the fold. The disclaimer and the quote contradict each other | Make the number the hero: **"~10 min/visit → 26 hrs a year on your phone at the gym."** |
| Arm story | Blue vs red arm, "Perfect Pump" | Not personalised (I said I don't time rests; never mentioned) | Tie to the answer: "You don't time rests. GymBlock does it automatically." |
| Records story | 10-cell table, % maths | Dense; "This looks motivating." is weak; weight × reps % needs a footnote to parse | Show one chart line (with vs without) and one sentence |
| Paywall | "View subscription" → Preview workout | CTA "View subscription" is off-putting; blocking not in benefits | CTA "Continue"; lead benefits with blocking |

**Mechanics**
- Each transition fades to a blank page; taps during the ~200 ms window are **silently dropped** (`OnboardingJourney.swift:377`). A fast double tap = lost answer. Queue the tap or shorten the fade.
- Progress bar spans 14 milestones, so it visibly crawls. Fewer screens fixes this.
- Ask **kg/lb** in onboarding (or on first weight entry). Today it's only in Settings.

## P1: Workout tab

### Home (idle)
- ~70% empty canvas. Shows "0 workouts this week", a giant "Free workout ⌄" that reads as a **heading, not a picker**, and Start workout.
- **Missing:** blocking status, last workout ("Push · 2 days ago"), suggested next split.
- **Recommendation:** Card stack: (1) Blocking status, (2) "Next: Pull day · Start" one-tap, (3) "Free workout" as a secondary button.

### Choose exercise (after Start workout)
- No running workout clock or "workout started" feedback, and no blocking indicator.
- Flat alphabet-less list, no muscle groups, no recents on first run (Recent appears only after history exists. Good, but the first-run list should be grouped).

### Set setup
- "Choose weight" is mandatory before Start set is enabled (`Session.swift:62`). A first-time user who just wants to time a set is blocked.
- **Weight picker:** wheel starts at "Bodyweight", 0.5 kg steps, range 0–500. Reaching 60 kg means scrolling past 120 values. "Type weight" is an extra tap and **isn't remembered**; the sheet reopens on the wheel every time.
- **Recommendation:** Inline stepper on the main screen: `[−2.5]  60 kg  [+2.5]`, tap the number to type. Remember the last-used mode. Allow Start set without a weight (log it after).

### Active set
- Good: reps pre-filled, ± buttons, big number, live set clock.
- Set clock is 20 pt body text. For a timing app, it should be prominent.
- Show **"Set 2 of 3"** using the onboarding/split target.

### Rest
- Good: large count-up, last set, next weight.
- **Missing:** a target rest / countdown, plus a notification or haptic at the target. The onboarding promised "Time your rests" but there's no target to time against. A rest-done local notification is table stakes (user's phone is locked/blocked).
- "End workout" one-tap problem (P0 #2).

### Exercise switching
- Splits don't auto-advance; the user must open the chevron sheet each time (`Model.swift:189`, no next-exercise logic). For a 6-exercise split, that's 12 extra taps + 6 weight entries per workout.
- **Recommendation:** After the target sets for an exercise, Rest screen shows "Next: Incline press →" as the primary action.

### Summary
- "1 sets" pluralisation bug (also on History rows and onboarding wheel).
- Shows minutes, sets, reps, weight moved. **Missing both differentiators:** time protected from scrolling / apps blocked, and avg rest vs target.
- Add a comparison to the last time ("+5 kg on bench").

## P2: History, Splits, Settings

**History**
- Headline metrics are total reps and "Weight moved". Those are vanity numbers for most lifters. Lead with **workouts this week / streak** and **PRs**.
- Workout rows show "Free workout · 1 sets · 1 min" but not which exercises.
- The period filter is a top-right capsule; fine.

**Splits**
- A whole tab for an optional feature that, today, saves only a few taps (no auto-advance, no targets). "Free workout" appears as a row in the split list, which is confusing.
- **Recommendation:** Fold splits into the Workout tab ("Your splits" section on Home) and drop to 2 tabs (Workout / History) unless splits gain real behaviour (targets, auto-advance).

**Settings**
- Blocking ("Focus demo") is the 2nd row of the 2nd group, peer to "Data". It should be the first section.
- Name field ("Optional") has no visible purpose.

---

## Cross-cutting copy & polish
- Pluralisation: "1 sets" appears in 3 places. Use `^[\(n) set](inflect: true)` or a helper.
- "workout" (noun) vs "work out" (verb) in the frequency question.
- Disclaimers ("Stylized model · Not measured…", "Visual metaphor · Not a nervous-system measurement") stack up and undercut the stories. Keep honesty, but consider one footnote per story rather than a caption under each animation.
- Screenshot timing showed brief blank frames between onboarding steps; consider a cross-fade that doesn't go fully to empty.

---

## Suggested order of work
1. P0 #2 (End confirm) and #3 (digit drop): small code changes, high risk.
2. P0 #4: remove the dev annotation.
3. Inline weight stepper + remember type mode.
4. Blocking setup step + Home status row + default ON.
5. Onboarding consolidation (17 → ~8 screens): scrolling Q first, merge reps/sets/exercises, personalised hero number.
6. Rest target + notification; "Set n of N"; split auto-advance.
7. Summary/History metrics; fold Splits into Workout.
