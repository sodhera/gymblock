# GymBlock — Developer Guide

Native SwiftUI, iOS 26.1+, iPhone only. The project is generated by
**XcodeGen** from `project.yml`. `GymBlock.xcodeproj` is gitignored, so
regenerate it after pulling or adding files.

```bash
brew install xcodegen      # once
xcodegen generate
open GymBlock.xcodeproj
```

Build and test from the command line:

```bash
xcodebuild -project GymBlock.xcodeproj -scheme GymBlock \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
xcodebuild test -project GymBlock.xcodeproj -scheme GymBlock \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

## Targets

| Target | What it does |
| --- | --- |
| `GymBlock` | the app |
| `GymBlockShieldConfig` | draws the shield over blocked apps ("3 sets of Bench Press left") |
| `GymBlockShieldAction` | handles the shield button (closes the app; no escape hatch) |
| `GymBlockMonitor` | safety cap: clears the shield if a workout outlives 4h |
| `GymBlockTests` | streak / PR / onboarding-math / catalog tests |

`Shared/` is compiled into all four targets. It holds the app-group mirror
of the running workout (`SharedWorkoutState`), the named settings store
(`.gymblock`), and the safety activity name. App group:
`group.com.sulav.gymblock`.

Family Controls is only in the **device** entitlements for the extensions
(`*-device.entitlements`, selected via `CODE_SIGN_ENTITLEMENTS[sdk=iphoneos*]`),
the same pattern as SleepBlock. Screen Time doesn't work in the Simulator.
The UI says "Blocking needs a real iPhone" there. Distribution requires
Apple's Family Controls entitlement approval for all four bundle IDs.

## Configuration

`GymBlock/Config/Secrets.xcconfig` (committed) declares empty keys and
includes the gitignored `Config.xcconfig`. Copy
`Config.xcconfig.example` → `Config.xcconfig` and fill in:

- `SUPABASE_URL`, `SUPABASE_ANON_KEY`. Empty = auth and friends disabled.
- `REVENUECAT_API_KEY`. Empty = **dev mode**: the paywall stands down and
  the app runs unlocked.

### Supabase

1. Create a project and run `supabase/migrations/001_init.sql`.
2. Enable the Apple provider (Auth → Providers) with bundle ID
   `com.sulav.gymblock`.
3. Deploy the deletion function: `supabase functions deploy delete-account`.

The schema's RLS enforces the privacy model: friends see summaries and PRs
always, and workout details only when the workout is shared.

### RevenueCat

Create an entitlement named exactly **`GymBlock Pro`** and a current
offering with annual (with a free-trial intro offer) and monthly packages.

## Debug launch arguments (Debug builds only)

| Argument | Effect |
| --- | --- |
| `-reset` | wipe local data on launch |
| `-skip-onboarding` | mark onboarded, starter templates, skip auth and primer |
| `-demo-history` | ~10 weeks of plausible workouts for design review |
| `-preview-paywall` | show the real paywall with fake plans (no StoreKit) |

In the Simulator without Supabase, the account step offers
**"Skip — dev build, no Supabase"**.

```bash
xcrun simctl launch booted com.sulav.gymblock -reset -skip-onboarding -demo-history
```

## Architecture

- `AppStore` (`Store/AppStore.swift`) is the single `@Observable` source of
  truth. It owns persistence and routing (`route`: launching → onboarding
  → paywall → primer → main) and exposes intents: `startWorkout`,
  `toggleSetDone`, `finishWorkout`, templates, friends.
- **Persistence:** Codable JSON files in Application Support
  (`Persistence.swift`). Decoders tolerate missing keys, so new fields
  never break saved data.
- **Services** sit behind protocols with disabled/no-op fallbacks:
  `AuthProviding` (Supabase), `SubscriptionProviding` (RevenueCat),
  `FriendsProviding` (Supabase PostgREST), and `ScreenTimeController`
  (FamilyControls + ManagedSettings + DeviceActivity).
- **Derived numbers** (`Models/Training.swift`) are pure functions:
  `Streak.week`, `Streak.weeks`, `Streak.consistency`, `Records.best`,
  `Records.previousSets`. Friends' rows go through the same math, so the
  two can never drift.
- **Rest timer** is wall-clock based (`RestTimer`) and backed by a local
  notification.
- **Exercise catalog:** `Models/ExerciseCatalog.swift`, about 150
  hand-curated lifts. IDs are permanent (they're stored in every workout).
  Rename freely, but never change an ID.

## Conventions

- Read `DESIGN.md` before changing UI, and update it when a design
  decision changes (note retired directions and why).
- Every button fires a haptic through the shared button styles. Use the
  named patterns in `Haptics.swift`, not ad-hoc generators.
- No exercise figures or illustrations (a product decision; see
  DESIGN.md).
- Commit often with conventional prefixes (`feat:`, `fix:`, `design:`,
  `chore:`).
